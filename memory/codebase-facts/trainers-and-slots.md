## Trainer System

**Three-file system**: `opponents.h` (IDs), `trainers.h` (metadata + macro), `trainer_parties.h` (party struct). All three must match. Macro/struct mismatch = crash. Validation: `scripts/check_trainers.sh`.

**Capacity**: TRAINERS_COUNT = 891; unreferenced IDs 633,634,853 (486 → TRAINER_FORTREE_CHARM_KEEPER C375, by the C369 recipe: hand rename + modify mode; 485 → TRAINER_MAUVILLE_GYM_HOPEFUL C369; 462 → TRAINER_ROUTE109_STORM_WATCHER C368; 581 → TRAINER_PYRE_MOURNER C334; 117 → TRAINER_ROUTE119_STORM_CHASER C349; 173 → TRAINER_ROUTE113_ASH_CAMPER C350). Hand-verify each (computed-ID refs are invisible to the scan) before use; never bump TRAINERS_COUNT. 568 = TRAINER_JUAN_DUET (C322); 851/852 = TRAINER_MAXIE_RECKONING/TRAINER_ARCHIE_RECKONING (C326, constants renamed from TRAINER_RED/LEAF, arrays sParty_MaxieReckoning/ArchieReckoning). Link path is safe for reclaimed slots: `gTrainers` is `const` (ROM), and TRAINER_LINK_OPPONENT = 2048 is handled outside the table. Never bump TRAINERS_COUNT: SYSTEM_FLAGS follows TRAINER_FLAGS_END, so a bump breaks old saves. Rematch table: 5 tiers, all filled. **Repurposed slots**: TRAINER_WALLACE(+REMATCH_1-4) = Steven (C308); TRAINER_JUAN_1-5 = Wallace (C309) — constant names kept for those. 568 TRAINER_GRUNT_UNUSED → TRAINER_JUAN_DUET (C322) and 851/852 → *_RECKONING (C326) were renamed. **Reclaim a slot** (by hand): rename constant + `[ID]` block + party array first (modify mode finds the array by the config `partyName`, so it must already carry the new name), then run generate_trainer.cjs in modify mode (it rewrites the array and the `.party` macro/struct only; class/music/pic/name/items/doubleBattle/aiFlags are hand-edited, e.g. a reclaimed Twins slot stays `.doubleBattle = TRUE` until you change it).

**Double-battle trainers get fixed personalities** (`battle_main.c` CreateNPCTrainerParty): `doubleBattle == TRUE` → base personality 0x80 plus the trainer-name hash << 8, so the low byte is always 0x80. Ability is always slot 0, and gender is fixed per species (0x80 against the gender threshold: Luvdisc female, 50/50 species male). Don't build a doubles boss around a slot-1 ability (Lightning Rod Marowak, Water Absorb Mantine). When a doubles trainer's mon faints, `GetMostSuitableMonToSwitchInto` (battle_ai_switch_items.c) picks the replacement by type matchup, not party order, so planned "pairs" mix after the first KO.

**Tag/multi battles load at most 3 mons per opponent** (`battle_main.c` CreateNPCTrainerParty: `BATTLE_TYPE_TWO_OPPONENTS` → monsCount = PARTY_SIZE/2). Mossdeep Space Center (SPECIAL_BATTLE_STEVEN) is one, so any boss fought in a tag battle needs a ≤3-mon array or slots 4+ (often the ace) silently never appear. C316 fixed sParty_MaxieMossdeep (was 4 mons, Camerupt ace cut).

**Villain parties (C316)**: all 10 Maxie/Tabitha/Archie/Shelly/Matt arrays are generated from `scripts/trainer_configs/villain_*.json`. Ownership/collision check: `node scripts/audit_boss_species.cjs [--strict]` (BOSS_GROUPS regex map → per-boss species, ACCEPTED_OVERLAPS with allowed pairs, `COLLISIONS: N`; exit 1 only under --strict). Grunts/route trainers are not audited.

**Rival parties**: 30 arrays (5 encounters × 3 starter variants × 2 genders, mirrored). Postgame (C280): Lv70-73, 6 mons, IV 200, ace = Changed Three form.

**Sighted trainer with a gated intro = twin objects (C375, FortreeCity 3,7)**: CheckTrainer (trainer_see.c / battle_setup.c) reads the trainer flag and battle type from the FIRST bytes of the object's script, so a sight > 0 trainer's script must start with `trainerbattle` and can't `goto_if_set` before its intro. For a flag-dependent intro, put two objects on the same tile with the same trainer and different scripts, and have ON_TRANSITION hide exactly one with temp flags (FortreeCity: plain twin flag FLAG_TEMP_6, turned twin FLAG_TEMP_5 shared with the 3 LOTAD DOLLs; OnTransition `goto_if_set FLAG_ROUTE104_SKEPTIC_TURNED` → setflag FLAG_TEMP_6, else setflag FLAG_TEMP_5). Post-defeat pose: `call_if_defeated TRAINER_X` → setobjectmovementtype on BOTH twins. check_object_tiles printed nothing for two start objects on one tile (C375). After a sighted battle the trainer stays on the tile it walked to (3,8) until the map reloads, then respawns on its template tile. A beaten sighted trainer spots no one. Playtest a sighting with `walkTo` ending ON the spotting tile, then `talk {start: false}` (reads the intro box the sighting script shows; no A press), then `waitFor battle` (verified C375: fortree-charm-keeper-spots-player/-ungated).

**Pokénav leader entries**: `MatchCallStructTrainer.name = NULL` means name and pic come from `gTrainers[gRematchTable[rematchTableIdx].trainerIds[0]]` (pokenav_match_call_list.c / pokenav_match_call_data.c). Renaming a trainer in trainers.h renames its Pokénav entry; only `.desc` (strings.c) and the flavor texts (match_call_messages.h) are separate.

**Trainer mon internals (C308)**: ability = slot 0 always (personality bit0 = 0); nature from trainer-name + species-name hash; Challenge mode adds per-class levels (include/challenge_mode_scaling.h, CHAMPION +5). Crit stages: battle_script_commands.c Cmd_critcalc (high-crit move, Scope Lens, Tempered Blade on Steel contact each +1). **VAR_STARTER_MON**: 0 Larvitar, 1 Bagon, 2 Dratini (src/starter_choose.c) — Changed Three are NOT starters (wild + Birch postgame gift).
