- **Birch dex rating / match call text** (C319): the Pokénav Birch call goes `MatchCall_GetMessage_Birch` (pokenav_match_call_data.c) → `BufferPokedexRatingForMatchCall(gStringVar4)` (match_call.c). It builds one string with `CHAR_PROMPT_CLEAR` between pages (each page is a button press). `StringExpandPlaceholders` returns a pointer to the EOS it wrote, so you can append by overwriting that EOS with `CHAR_PROMPT_CLEAR` and expanding again. gStringVar4 is 0x3E8 bytes. The in-person rating is a separate script path (`ProfBirch_EventScript_AskRatePokedex` → `..._RatePokedex` in data/scripts/prof_birch.inc), so any rating addition has to be written twice: in C for the call and in script for the visit. The Champion's Room also calls `..._RatePokedex`. Field Notes live in `AppendBirchFieldNotes` / special `IsBirchFieldNoteActive` (reads VAR_0x8004). C331 pattern to avoid writing it twice: one `static u8 *Write…(u8 *str)` writer, called by the match-call builder and by a special that writes gStringVar4 and returns TRUE/FALSE. The script does `specialvar VAR_RESULT, X` → `goto_if_eq VAR_RESULT, FALSE, Common_EventScript_NopReturn` → `msgbox gStringVar4` (see `WriteBirchRedInkReport` / `BufferBirchRedInkReport`). check_text_width only sees `.string` lines, not whether C joins them, so hand-cap C-joined Pokénav text at ~28 chars/line. **Lab talk routing (C357/C358, playtests birch-*):** LittlerootTown_ProfessorBirchsLab_EventScript_Birch runs BookshelfGreeting first, then with FLAG_SYS_GAME_CLEAR goes to BirchQuestCheck: a pending Reckoning payoff ends the talk; otherwise BirchLab_ReckoningCheckDone first calls PostgameRedInkOffer (3+ inked, once per lab visit via FLAG_TEMP_1: the AreYouCurious YES/NO, then RatePokedex/FieldNotes/RedInkReport) and then the migration quest. Pre-credits, Birch in the lab needs VAR_PETALBURG_GYM_STATE != 0 and VAR_BIRCH_STATE 0/1/6/7; FLAG_HAS_MATCH_CALL unset or FLAG_ENABLE_PROF_BIRCH_MATCH_CALL set reaches AskRatePokedex.

- **Field Notes margins (C334)**: `BufferFieldNotesPage` shows a page's `marginText` only when `IsFieldNotesMarginEarned(i)` (match_call.c, after IsFieldNotesPageInked): P1-P4 TRUE (margin follows the ink); den pages need their believer: TORCHIC = `HasTrainerBeenFought(TRAINER_PYRE_MOURNER)` (battle_setup.h, = FlagGet(TRAINER_FLAGS_START + id)); MUDKIP = `FlagGet(FLAG_DEN_SHOAL_TRADE_DONE)` (C335); TREECKO returns FALSE until C336. `WriteBirchRedInkReport` adds one `gBirchRedInkText_Dens` line when any den page is inked AND earned; ending = Believed if a P1-P4 believer was named, else OnlyYou only if no den word, else no ending line. Field-notes/red-ink externs live in match_call.c's extern block, not include/strings.h.

- **Field Notes p.3 doubt box (C340)**: `BufferFieldNotesPage` appends a 4th box to page 3 only (`i == FIELD_NOTES_GLIGAR && FlagGet(FLAG_LILYCOVE_GLIGAR_DOUBT)`), after the margin, still inside the `IsFieldNotesPageInked` block (so it can never show on an uninked page). The margin's `StringExpandPlaceholders` return is now kept in `str` so further boxes can chain; any new per-page box follows the same `*(str++) = CHAR_PROMPT_CLEAR; str = StringExpandPlaceholders(...)` pattern. Not in `sFieldNotesPages`, `IsFieldNotesMarginEarned`, `WriteBirchRedInkReport` or the Pokénav path: Birch never sees it. `check_matchcall_len` adds `gFieldNotesText_<Page>Doubt` to that page's length if the label exists (Gligar 279 B).

Ordering (C350 Route 113): a later `setobjectmovementtype` in the same OnTransition overrides the movement the DexBelieverPlace macro set (both write the template; last write wins), so post-event facings are called AFTER the macro line. **C362: the Route 104 skeptic no longer uses DexBelieverPlace**: his east facing on load is `call_if_set FLAG_ROUTE104_SKEPTIC_TURNED, Route104_EventScript_SkepticFacesEast` (0x35), set only by his first talk with LOTAD_HOENN caught (`Route104_EventScript_LotadSkepticPenLine`: Recites text, `Common_Movement_ExclamationMark`, setflag, Corrected, FaceRight). Facing follows the flag, dialogue follows the dex (`believer-skeptic-flag-alone-faces-sea` pins this). The postgame `SetupLotadLesson` still runs after it and overrides to FACE_DOWN; the Lesson branch never sets the flag. Pattern for a turn the player must witness: gate the persistent pose on a flag the talk sets, not on the dex. **C363 forager walk-off (same pattern, plus a relocation):** walk her out with `applymovement` (scripted movement ignores collision, so check the path with map_scan: a ledge row will be walked straight over), then `setobjectxy` (moves the LIVE object at once, so only do it while she is off-screen: screen = player ±7 columns, about ±5 rows) and `setobjectxyperm` (template only, shows on the next map load) to the same tile, then `setobjectmovementtype` + `turnobject`. Off-screen objects aren't despawned mid-script (RemoveObjectEventsOutsideView runs on camera moves), so the live object survives until the player walks. `getplayerxy VAR_TEMP_0, VAR_TEMP_1` picks a route when the player blocks the default one.
