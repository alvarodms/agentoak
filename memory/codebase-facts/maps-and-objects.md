## Wild Encounter JSON Rules

**File**: `src/data/wild_encounters.json`. Land: 12 slots (20/20/10/10/10/10/5/5/4/4/1/1%). Water: 5. Fishing: 10.

**Conditional tables**: `GetCurrentMapWildMonHeaderId()` in `src/wild_encounter.c` (line 305). Alternate entry MUST follow base entry in JSON.

**Shoal Cave tide architecture**: `ShoalCave_LowTideEntranceRoom` handles BOTH tides — `OnTransition` calls `UpdateShoalTideFlag` then swaps layout. Object events on `LowTideEntranceRoom` appear in both tides. Use `call` subroutine pattern for OnTransition logic. **FLAG_SYS_SHOAL_TIDE SET = HIGH tide.** Only the Entrance and Inner rooms swap layouts (`setmaplayoutindex`), so their objects/bg_events exist at both tides (a sign there needs tide-aware text and a stand tile walkable in both layouts). The Lower, Stairs and Ice rooms are **low-tide-only maps**: at high tide the Inner Room warps to the Lower Room (4 at (15,19), 5 at (30,25)) sit on MB_OCEAN_WATER, and water is not in `IsWarpMetatileBehavior` (field_control_avatar.c:751), so they never fire; warp 3 (ladder at (19,14), elevation 4) is unreachable by walking or surfing. Surf can only start from elevation 3 and `CanStopSurfing` only lands on elevation 3 (field_player_avatar.c:729). Ledges (MB_JUMP_*) have collision 1 but `ShouldJumpLedge` runs before the collision check. Throwaway map.bin BFS recipe: u16 per tile, metatile bits 0-9, collision 10-11, elevation 12-15; behavior = low byte of `data/tilesets/{primary/general,secondary/cave}/metatile_attributes.bin` (secondary index = metatile-512).

## Repel System Architecture (C295, shipped C297)

**Script**: `data/scripts/repel.inc` — BW-style continuation prompt. Shows "REPEL's effect wore off", calls `Special_FindBestRepelInBag` to find best available (Max > Super > Repel), prompts "Would you like to use another {item}?", calls `Special_UseRepelFromBag` on yes.

**C helpers**: `src/field_specials.c` — `Special_FindBestRepelInBag()` sets `gSpecialVar_Result` to best item ID (or 0). `Special_UseRepelFromBag()` reads `gSpecialVar_0x8004`, calls `RemoveBagItem` + `VarSet(VAR_REPEL_STEP_COUNT, GetItemHoldEffectParam(...))`.

**Infrastructure**: `wild_encounter.c:883` calls `ScriptContext_SetupScript(EventScript_RepelWoreOff)`. `item_use.c:843` sets the var for manual use.

## Small Systems

- **Legendary battle**: `setwildbattle` -> `setflag` -> `special BattleSetup_StartLegendaryBattle` -> `waitstate` -> check `B_OUTCOME_CAUGHT`. Macros: `asm/macros/legend_macros.inc` (7 composable).

- **Static Encounter Recipe** (C315 rewrite): `removeobject` SETS the object's flag (RemoveObjectEventByLocalIdAndMap → FlagSet, `src/event_object_movement.c:1394`), so the vanilla recipe (object flag = FLAG_HIDE_X, Faded path → `Common_EventScript_RemoveStaticPokemon`) hides the Pokémon PERMANENTLY after a KO/flee — the C312 Mt. Pyre bug. **Den pattern (C315)**: object_event `flag` = `FLAG_TEMP_11` (temp flags clear in ClearTempFieldEventData on every map load, `src/overworld.c:798/848`, but NOT on return from battle) + a permanent `FLAG_CAUGHT_*` set only on `B_OUTCOME_CAUGHT`. Three macros in `event_macros.inc`: `EventMacro_StaticDen species, level, item, caught_flag, approach_text, caught_text, faded_text` (whole interact script: lock → msg → cry → `setwildbattle` (3rd arg = held item) → `setflag FLAG_SYS_CTRL_OBJ_DELETE` → `dowildbattle` → clear; CAUGHT → setflag caught + caught text; any other outcome → faded text + `Common_EventScript_RemoveStaticPokemon`; whiteout aborts the script so the doll stays); `EventMacro_StaticDenTransition caught_flag, temp_flag` (inline in MAP_SCRIPT_ON_TRANSITION before `end`; sets the temp flag if caught, so the object never spawns); `EventMacro_StaticDenTryRemove` (body of the ON_RESUME subroutine reached via `call_if_set FLAG_SYS_CTRL_OBJ_DELETE, ...`; removes the sprite only after a catch). A new den = 1 flag + 1 object (FLAG_TEMP_11, doll gfx, FACE_DOWN, no faceplayer: dolls are single-frame) + ON_TRANSITION/ON_RESUME entries + 1 macro line. Users: MtPyre_Exterior (Torchic), MeteorFalls_B1F_2R (Treecko), ShoalCave_LowTideLowerRoom (Mudkip, FLAG_TEMP_12). Check the map uses no other copy of that temp flag first. `make check_dens` (C319) verifies all of this wiring statically (C352: `--selftest && real run`; rules run through a pure `check({mapNames, maps:{<map>:{json, script}}, flagsH})` → `{errors, dens}`, selftest plants a duplicate FLAG_TEMP_* object, a removed StaticDenTransition and a clashing FLAG_CAUGHT_* value). **When ON_TRANSITION runs** (checked C336): only from `LoadMapFromCameraTransition` (walking across a map connection, overworld.c:807) and `LoadMapFromWarp` (:860). Return from battle and menus go through `CB2_ReturnToField` → ON_RESUME only, and Continue (`CB2_ContinueSavedGame`) also skips it unless a continue-game warp is set. So an OnTransition gate on a flag set during the visit (B1F_2R `NewChalk` sets FLAG_TEMP_13 if the Treecko is caught) changes the room only after the player leaves and warps back in. **Live post-catch reactions** (C338): pass a subroutine as EventMacro_StaticDen's optional 8th arg `on_caught` (called after caught_text, same visit, must end in `return`), since ON_TRANSITION does not run on battle return; pair it with an OnTransition `call_if_set <caught_flag>` that sets the same end facing for re-entry.

- **In-game trades (C335)**: `sIngameTrades[]` (src/data/trade.h, `struct InGameTrade` in trade.c:150) is an unsized array indexed by `INGAME_TRADE_*` (include/constants/trade.h, already #included by data/event_scripts.s); no count constant. Adding one = new constant + entry. `CreateInGameTradePokemonInternal` (trade.c) uses the fixed `.personality` (gender = low byte vs the species' genderRatio, nature = personality % 25) and `OT_ID_PRESET` `.otId`; level = the offered mon's level; met location METLOC_IN_GAME_TRADE. Mail is only built when `ItemIsMail(heldItem)`; non-mail entries write `.mailNum = -1`. `GetInGameTradeSpeciesInfo` buffers STR_VAR_1 = requested, STR_VAR_2 = offered species name and returns the requested species; `GetTradeSpecies` returns SPECIES_NONE for an egg, so the script's species compare rejects eggs. Script chain to copy: RustboroCity_House1_EventScript_Trader (VAR_0x8008 trade id, 0x8009 requested species, 0x800A party slot). check_gifts Rule D lints both species fields.

- **Field-move targets are found by object graphicsId only** (C348): Cut / Rock Smash / Strength look for OBJ_EVENT_GFX_CUTTABLE_TREE / BREAKABLE_ROCK / PUSHABLE_BOULDER regardless of script or flag (fldeff_cut.c:147 → fldeff_rocksmash.c:30), so never use those graphics as scenery.

- **FACE_* NPCs keep facing the player after `faceplayer`** (C330 trace): MovementType_FaceDirection only sets the facing in step 0 and then idles, so after release the NPC keeps looking at the player until the map reloads. To snap back in-scene: `applymovement LOCALID_X, Common_Movement_FaceOriginalDirection` (direction from the movement type) or `Common_Movement_FaceUp` etc. (data/scripts/movement.inc), then `waitmovement 0`.

- **Map-load metatile traces (C356, Route113_OnLoad)**: MAP_SCRIPT_ON_LOAD runs from InitMap and from InitMapFromSavedGame (fieldmap.c), after LoadSavedMapView, so a `setmetatile` there shows on warp-in, connection walk-in and Continue; it needs no DrawWholeMapView. Vanilla ash footprints (field_tasks.c AshGrassPerStepCallback: 0x20A → 0x212 via StartAshFieldEffect) live only in the map buffer and regrow on every load. 0x212 Fallarbor_NormalGrass is MB_TALL_GRASS (encounters, not re-trodden); CUT turns both 0x20A and 0x212 into AshField 0x218 (fldeff_cut.c). check_beat_visibility W1-W4 guard any ON_LOAD trace via its TRACES table. **Playtest probe for metatiles**: the playtest format cannot read a metatile, but with ITEM_SOOT_SACK in the bag each step onto MB_ASHGRASS increments VAR_ASH_GATHER_COUNT (`expectVar`), so ash vs trodden grass is observable. The per-step task starts with tPrevX/Y = 0, so a scenario starting ON ash grass counts its first frame: start on a non-ash tile. Add VAR_REPEL_STEP_COUNT + a Lv100 lead so tall grass doesn't start a battle mid-walk.

- **Overworld Pokémon stand-ins**: `OBJ_EVENT_GFX_*_DOLL` (e.g. OBJ_EVENT_GFX_TORCHIC_DOLL=155, event_objects.h) work as visible wild Pokémon. Single frame, so skip `faceplayer` and use MOVEMENT_TYPE_FACE_DOWN.
