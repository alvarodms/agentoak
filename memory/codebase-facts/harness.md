# Playtest harness (src/emulator/) and playtest ROM presets

Moved verbatim from memory/codebase-facts.md in C380 (index: [../codebase-facts.md](../codebase-facts.md)). Current state, not a log: replace what a new fact makes redundant.

- **Playtest `talk`** (src/emulator/playtest.ts `talk()`): `talk` `answers: ["no"]` presses B on YES/NO boxes in order (C360, merged PR #224); unused answers fail the step. Default maxPresses is 200; a long chain (postgame Birch: rating + den hint + red ink report + 11-page quest hook ≈ 40 boxes) needs `{"talk": {"maxPresses": 600}}`. Transcripts (box order) are in artifacts/playtests/report.json `transcripts`; expectText doesn't check order, so read the order there. Objects with no local_id are addressed by 1-based map.json index (e.g. Lilycove ExpertF = 8).

- **`useKeyItem`** (C360) writes gSaveBlock1Ptr->registeredItem (+0x496) and presses SELECT; FIELD NOTES pages land in gStringVar4. The transcript decoder skips {COLOR} codes, so red ink is checked by screenshot only (`"read": false`, then `press A` + `wait 300` per box: every `\l` and `\p` waits for A; see field-notes-first-ink). C361: `"register": false` presses SELECT without writing the slot and fails unless the game already registered that item.

- **Harness battle/catch steps (C361, src/emulator/playtest.ts)**: `findWildBattle.species` waits for "What will", reads gBattleMons[1] and, if it's another species, picks RUN (RIGHT, DOWN, A from any cursor slot), taps B until CB2_Overworld and keeps walking (maxSteps counts walking steps; needs a fast lead). `catchWild {ball}`: finds the ball's list index in SaveBlock1 bagPocket_PokeBalls (+0x650, filled slots only), BAG = UP, RIGHT, A from any slot; waits for CB2_BagMenuRun; reads gBagPosition (pocket @5, cursorPosition[5] @8, scrollPosition[5] @18) to switch to BALLS_POCKET (1) with LEFT/RIGHT and move the cursor; A, A (USE); then taps B through "Gotcha!", the dex message, the new-dex page (A|B closes it, pokedex.c Task_HandleCaughtMonPageInput) and the nickname YES/NO (B = no, battle_script_commands.c trygivecaughtmonnick); requires gBattleOutcome == 7; clears gStringVar4; returns once a field script started or the field is idle twice in a row. Scenario `registeredItem` is NOT in the ROM struct (layout v2 unchanged): bootScenario writes it the moment CB2_Overworld appears, before any script can wait on A. Real-catch run on Route 102 22,8 ⇄ 23,8: ~20k frames, ~10 s.

- **Harness `warp` step (C362, src/emulator/playtest.ts `warp()`)**: `{"warp": {"map": "MAP_X", "x": n, "y": n}}` does what WarpIntoMap + Task_WarpAndLoadMap do, from outside: copies gSaveBlock1Ptr->location to gLastUsedWarp, writes struct WarpData (s8 group, s8 num, s8 warpId=-1, pad, s16 x, s16 y; `encodeWarpData`) to sWarpDestination (static, nm still lists it) and to SaveBlock1 location (+0x04), sets SaveBlock1 pos (+0x00), gMain.state (+0x438) = 0 and gMain.callback2 = CB2_LoadMap|1 (Thumb; nm prints even addresses). The map loads fresh (ON_TRANSITION, ON_LOAD, objects respawn, default fade-in). Refuses while a script runs; fails unless the player lands on the tile. Unit tests pin the three offsets against global.h / main.h. Objects outside the camera window are not spawned (see failure-patterns C367). Walking a real door also works (C359: lab exit = walk onto 6,12 mat, press DOWN hold 20, wait 180; re-enter with walk up + wait 180); any real map change runs ClearTempFieldEventData, so FLAG_TEMP_* read false after (never set them by hand). Postgame Littleroot without intro scenes: VAR_LITTLEROOT_INTRO_STATE 7, VAR_LITTLEROOT_TOWN_STATE 4, VAR_LITTLEROOT_RIVAL_STATE 4, FLAG_RESCUED_BIRCH.

- **Harness `pokenavCall` (C365, src/emulator/playtest.ts `pokenavCall()`)**: drives the real menus, no C shortcut. Start menu: press START, wait for gMenuCallback == HandleStartMenuInput (static, start_menu.o); read the statics sNumStartMenuActions / sCurrentStartMenuActions[] / sStartMenuCursorPos (nm lists statics; `symbols.address(name, "src/start_menu.o")`), find MENU_ACTION_POKENAV (3) and press UP/DOWN until the cursor matches (it remembers its last position across opens). The whole Pokénav runs on one CB2 (static CB2_Pokenav, pokenav.o), so the screen name says nothing: readiness = the active gTasks entry whose func is Task_Pokenav has tState (data[0], task +8) == 3 (waiting for input; 2 = a menu animation, input is ignored). gPokenavResources (global ptr): +4 currentMenuIndex = POKENAV_* id - 100000 (main menu 0/1/4/5, match call 11), +16 substructPtrs[] (MAIN_MENU_HANDLER 1: menuType @0, cursorPos s16 @2; MATCH_CALL_MAIN 5: optionCursorPos @0, numRegistered @10, initFinished @16, callback @24, entries @28 of {u8 isSpecialTrainer, u8 mapSec, u16 headerId}). MATCH CALL is main-menu cursor 2 whenever FLAG_ADDED_MATCH_CALL_TO_POKENAV is set (menuType 0 = no Match Call). The list is special headers in MC_HEADER order (Mr. Stone's flag is 0xFFFF, always row 0; Birch = header 1, row 1 when enabled), then registered rematch trainers. A on a row → callback CB2_HandleMatchCallOptionsInput with option 0 = CALL; CALL → CB2_HandleCallExitInput immediately, the text printer then waits for A per page; the call is done when tState is 3 again with that callback. The whole call text is in gStringVar4 from the start (CHAR_PROMPT_CLEAR between pages; the menus also print through gStringVar4, so clear it just before CALL). Leaving: B hangs up → list → main menu → POKéNAV exits to CB2_ReturnToFieldWithOpenMenu (start menu open, sLockFieldControls set) → B closes it. Calls fail with gText_CallCantBeMadeHere on maps where Fly isn't allowed (use an outdoor tile; Littleroot 7,17 with the postgame Littleroot vars). Scenario FLAG_SYS_NATIONAL_DEX now runs EnableNationalPokedex in Playtest_ApplyScenario (src/playtest.c), because IsNationalPokedexEnabled also needs pokedex.nationalMagic 0xDA and VAR_NATIONAL_DEX 0x302. Regional forms do not count in the Hoenn dex (a 7-form scenario rates 0 seen / 0 caught Hoenn, 7/7 national).

- **Harness checkpoints + expectBoxCount (C367, src/emulator/checkpoints.ts)**: scenario `"checkpoint": "slateport_arrival" | "mauville_pre_wattson" | "fortree_arrival"` (the last standalone, C372: 17 flags, 2 vars, FortreeCity 0,8) is resolved by `applyCheckpoint()` inside `resolveScenario()` (scenario.ts) before scenarioConstants/encodeScenario: checkpoint flags ∪ test flags (a test clearFlag drops the checkpoint flag and vice versa), vars merged test-wins, tile = test's map/x/y only if all three given (zod refine + applyCheckpoint both reject a partial tile). Refuses FLAG_TEMP_*/VAR_TEMP_* keys (reset on every warp). Both checkpoints use 34/41 flags + 2 clearFlags of LIMITS.flags 64 (unit test keeps 20 free). Story values with evidence: Briney at Route 109 = VAR_BRINEY_LOCATION 3 (event_scripts.s:591/651) + clearFlags FLAG_HIDE_ROUTE_109_MR_BRINEY/_BOAT + the other 6 Briney hide flags set (event_scripts.s:615-621); Dewford→Route 109 sail ends with the player on **21,23** facing down (DewfordTown/scripts.inc:572-576 ExitBoatSlateport walks up 3 from the boat at 21,26; Briney up 2 to 21,24). Post-Slateport/Route 110: FLAG_DELIVERED_DEVON_GOODS (OceanicMuseum_2F:80), FLAG_HIDE_SLATEPORT_CITY_TEAM_AQUA + FLAG_DOCK_REJECTED_DEVON_GOODS (SternsShipyard_1F:17-18), VAR_SLATEPORT_HARBOR_STATE 0 (1 only after Magma Hideout), VAR_ROUTE110_STATE 1 (Route110:478), VAR_REGISTER_BIRCH_STATE 2 (Route110:634), VAR_SLATEPORT_OUTSIDE_MUSEUM_STATE 3 (2 would arm the Slateport 10,13 Scott coord event). Mauville Wally/uncle hide flags and FLAG_DEFEATED_WALLY_MAUVILLE are clear after new_game.inc (no script sets the hide flags; only removeobject/MauvilleCity:158), so "scene pending" needs no entry. **Boot runs ON_TRANSITION (checked C368)**: CB2_NewGame (overworld.c ~1533) → Playtest_ApplyScenario (SetWarpDestination + WarpIntoMap, playtest.c ~155) → DoMapLoadLoop → LoadMapInStepsLocal case 0 → LoadMapFromWarp → ClearTempFieldEventData then RunOnTransitionMapScript, all before objects spawn (case 3). So a checkpoint/scenario test that boots onto a map sees its ON_TRANSITION effects (FLAG_TEMP_* hides, setobjectmovementtype facings) with no `warp` step (route109-storm-watch-* rely on it). `expectBoxCount: N` counts `messageBoxes(transcript)` = the last talk's entries minus `[screen:`/`[answered` markers; one msgbox is one entry however many \p pages it has. **expectBoxCount / expectText / expectNoText need a prior `talk` step** (they fail "no talk step ran before this box count"); to prove "no scene fired" on boot, use `waitFor overworld` (waits for the field script to finish too) plus a `walk` step (a locked player can't move). **Trainer battles in this ROM**: CreateNPCTrainerParty (battle_main.c ~2052) is vanilla (personality 0x88/0x78 + species-name hash << 8; fixedIV = iv*31/255) plus challengeBoost, a level add only when Challenge Mode is on; ABSORB/MEGA DRAIN are Special (P/S split), so GROWL does not slow them.

- **Connection crossings in playtests (C377)**: `walk` over a map edge runs the new map's ON_TRANSITION, but objects of the map you left stay loaded while within x-9..x+10 / y-7..y+9 of the player (RemoveObjectEventIfOutsideView), so a `setobjectmovementtype` there only reaches objects that respawn. One step out and back leaves Fortree's keeper FACE_DOWN; walk out of that box first. `expectBoxCount` reads the last `talk`, so to assert "no arrival text" press A at an empty tile (`talk: true`) first. `object()` matches local IDs regardless of map, so `absent` on the other map is still sound (a stale object would match). There is no `expectTrainerDefeated` step (C377 added it, the runner rolled it back, C378 deleted its uses): a sighted trainer's intro box + battle prove her flag was clear, and her defeat text proves the win. **Screenshot after `battleTurns until` (C378)**: the step stops as soon as the message starts printing, so a screenshot right after shows a few letters; `wait 240` shows a full 2-line battle box.

- **Battle action menu / party menu (C376 `battleSwitch`)**: action menu is FIGHT (top left) / BAG (top right) / POKéMON (bottom left) / RUN (bottom right); DOWN+LEFT+A opens the party menu, which runs as gMain.callback2 = CB2_UpdatePartyMenu (party_menu.c; set after CB2_InitPartyMenu), cursor on slot 1, DOWN steps through slots; A → SHIFT/SUMMARY/CANCEL (SHIFT first), A again returns to BattleMainCB2. At the foe's "Will OAK change POKéMON?" YES/NO, tapping B answers NO.

- **Harness `battleTurns` (C370, src/emulator/playtest.ts `battleTurns()`)**: per turn UP+LEFT+A (FIGHT from any action), 30 frames, UP+LEFT (move slot 1 from any slot) + `MOVE_SLOT_PATH` (2 RIGHT, 3 DOWN, 4 DOWN+RIGHT), A. The move menu writes its PP/type strings into gDisplayedStringBattle, so it snapshots that text before the final A and waits until the battle text differs from it and has no "What will" before tapping B (B in the move menu would cancel). A turn ends at the next "What will"; it returns mid-turn as soon as every `until` string has shown, so a following `waitForBattleText "What will" fresh` or another `battleTurns` picks up the rest of that turn. Battle end = gMain.callback2 ≠ BattleMainCB2. **gBattleMons survives between battles**: a second battle in one test briefly shows the first battle's foe, so `expectBattle` now polls (600 frames) until the expected species/level appear. **Measured AI (C370)**: Wattson's LOTAD_HOENN 21 vs a Ground mon (CHECK_BAD_MOVE|TRY_TO_FAINT|CHECK_VIABILITY) uses CHARGE turns 1-3, MEGA DRAIN turn 4 (deterministic per frame timing, 43 dmg to a Lv50 SANDSHREW); TOBY's PLUSLE/MINUN take 5 + 8 ABSORB turns from a Lv18 Lotad_H.

- **Harness `hpPercent` + `battleSwitch` (SHIPPED C376)**: party field `hpPercent` 1-100 is validated in scenario.ts but not encoded; session.ts bootScenario writes hp = max(1, floor(maxHP*pct/100)) into gPlayerParty after boot (hp has no checksum; offsets pinned by a unit test vs pokemon.h + playtest.c offsetof). Step `{"battleSwitch": {"slot": 2-6, "forbid"?}}` at a "What will" prompt: POKéMON → DOWN to slot → SHIFT → runs the turn to the next "What will". `callbacks()` may print static CB2 names with an object suffix, compare with startsWith.

- **Scenario party `ability` (C364)**: 1/2 sets MON_DATA_ABILITY_NUM (PlaytestMon byte 0x03, layout v3; 0 = CreateMon's random pick). Pin it whenever a test depends on an ability (e.g. RAIN DISH Lotad_H = ability 2). A `waitForBattleText` gets 1800 frames (60 B taps); a faint + EXP + switch-in + end-of-turn weather/ability/status chain can run past that, so wait on an intermediate message first. Lotad_H in battle text is "LOTAD"; Thunder Shock prints "THUNDERSHOCK"; RAIN DISH prints "LOTAD's RAIN DISH restored its HP a little!" at end of turn only if HP < max.

- **New-game start / PLAYTEST (C339)**: CB2_NewGame (overworld.c) runs NewGameInitData then sets `gFieldCallback = ExecuteTruckSequence`, so any non-truck new-game start must swap the field callback too (the den tour uses FieldCB_WarpExitFadeFromBlack; WarpIntoMap after WarpToTruck simply overrides the destination). Anything run with RunScriptImmediately inside NewGameInitData must stay synchronous (setflag/setvar/givemon/setmonmove/additem/setrespawn; no msgbox, delay, warp or waitstate). `PLAYTEST` is a config.h constant (0; `make playtest` passes -DPLAYTEST=1, build/playtest, pokeemerald_playtest.gba). agbcc -O2 removes the dead constant branch (C344, verified by objdump -r): build/playtest/src/new_game.o references only EventScript_PlaytestDenTour, build/playtest_coda only EventScript_PlaytestCoda, and neither playtest overworld.o references ExecuteTruckSequence. FieldCB_WarpExitFadeFromBlack is referenced 3× by vanilla overworld.c, so its presence proves nothing. ScriptGiveMon sets SEEN+CAUGHT for MON_GIVEN_TO_PC as well as party. A badge-8 shortcut must also set the HIDE flags that a scene's `removeobject` would have set (Route 121 grunts, Meteor Falls Magma, Pyre summit Aqua/Archie, Lilycove rival/grunts are visible by default; EventScript_ResetAllMapFlags in data/scripts/new_game.inc lists the hidden-by-default ones).

## Cross-references (C380)

- **Boot runs ON_TRANSITION** (C372): a playtest boot (scenario map or checkpoint) runs the map's ON_TRANSITION, so checkpoint tests need no warp to set up conditional objects. - **Warp round-trip recipe** (C359): a door is a walk; an indoor exit mat (MB_SOUTH_ARROW_WARP) is walk on + press DOWN. Detail: failure-patterns.md "Playtest exit mats need a press, not a step".
- **Sighted-trainer playtest recipe** (C375): `walkTo` ending ON the spotting tile, `talk {start: false}`, `waitFor battle`. Detail: trainers-and-slots.md "Sighted trainer with a gated intro".

## Playtest ROM build facts (moved verbatim from project-facts.md C380)

- **Playtest ROM (C339)**: `make playtest` (from pokeemerald/) = `$(MAKE) PLAYTEST=1 rom` → `pokeemerald_playtest.gba`, objects in `build/playtest`, `-DPLAYTEST=1`. The runner/release only builds and ships the default `pokeemerald.gba`, so testers must build the den-tour ROM themselves (unless the runner learns to attach it). Default ROM is not byte-identical to pre-C339 (the den-tour script is always linked, never run).
- **Playtest ROMs are not runner-built** (C343): the runner's "Build: SUCCESS" covers only retail `make` (PLAYTEST=0). `make playtest` (PLAYTEST=1) / `make playtest_coda` (PLAYTEST=2) compile code under `#if`/`PLAYTEST ==` branches that retail never sees; build them by hand after touching new_game.c, overworld.c or data/scripts/playtest_*.inc.
- **Playtest ROMs compiled for the first time C344** (both clean on the first try, no new warnings; same memory use as retail, ROM 44.83%, EWRAM 95.26%, IWRAM 94.27%). Cold build ~45 s for PLAYTEST=1 at -j4 (generated graphics are shared in graphics/, only objects are per-variant), ~18 s for PLAYTEST=2; a relink after one .inc edit takes ~3 s. Sub-makes print "jobserver unavailable: using -j1" (harmless). **Rule:** any cycle that touches new_game.c, overworld.c, data/scripts/playtest_*.inc, or a flag/var named in those presets runs `make check_playtest_build` (two full builds + `$(OBJDUMP) -r` relocation greps; deliberately NOT in check_all). agbcc removes the dead `if (PLAYTEST == N)` branch (see codebase-facts "New-game start / PLAYTEST").
- **Battle measurement (C381-C382)**: `battleTurns` logs every battle message (and each "What will" prompt, plus a `[party hp% a,b,c]` marker when it returns) to `PlaytestResult.battleLog`; `summarizeBattles` turns that into `battleSummaries` in report.json (outcome win/loss/unknown, turns = prompts, faints per side by "Foe "/"Wild " prefix, end HP %). Step `expectBattleSummary {battle?, outcome?, min/maxTurns?, min/maxPlayerFaints?}` (default = last battle) prints the actual summary on failure. Use it for any difficulty hypothesis (PASS = faints; "forced switch" is unmeasurable because `replace: true` auto-sends). A battle that ends without a win/loss message merges with the next one. **faintCauses (C389)**: each summary with player faints has `faintCauses` keyed "FOE/MOVE" (species display name, so STANTLER_HOENN is "STANTLER") by the last `/^Foe (\S+) used (.+?)!$/` message before each player faint, "?" if none; chip damage (Leech Seed, poison) is credited to that last foe move, so read it as "who was acting", not exact damage. Report-only, no SummaryBounds field. **Turn timeout (C389)**: battleTurns fails a turn after 3600 frames with no NEW message (`idle`, reset per message) or 14400 in total (`TURN_FRAME_CAP`); before C389 it was 3600 per turn, which a doubles turn with two foe faints, four EXP messages and send-outs outran (Y7-GROUND turn 4 "still running", with the game waiting on an EXP bar, not hung). `expectFieldWeather` (C381) reads SaveBlock1 weather.
- **Yardstick gotchas (C384)**: (1) `battleTurns` repeats one slot, so a 5-PP slot-1 move (OVERHEAT) stalls: once it is out of PP every turn is "There's no PP left for this move!" and the step burns maxTurns. Script a line instead: `battleTurns move 1 until "Foe SKARMORY fainted"`, then `battleSwitch`, then spam (winona-sun-*). `battleSwitch` turns are not logged, so they are not in `turns`. (2) Don't stop a `battleTurns` on a message right before your own Pokémon faints: the forced party menu then opens outside any step and the next `battleTurns`' initial "What will" wait times out (B can't close that menu). Put the send-out message in `until` instead (`["SOLARBEAM", "PUPITAR fainted", "Go! HOUNDOOM"]` with `replace: true`), which also keeps the faint in battleLog. (3) A trainer facing down at x,y sees x,y+1 on load: read the intro with `talk: {start: false}`, not face+talk (fortree-gym-trainer-no-sun). (4) `expectBattleWeather` still reads the battle's weather after the win/loss message (gBattleWeather isn't cleared at battle end).
- **battleTurns `moveFor` (C387)**: optional map foe SPECIES_* → move slot 1-4 (exported `pickMoveSlot(moveFor, speciesName, move)`); falls back to `move`; reads battle[1].speciesName only when set (doubles: left foe only); logs `[moveFor SPECIES_X → slot N]`. It keys on the foe, not on your active mon, so align slots by role across the party (route119-rival-rain-coverage-*).
- **In-game partner battles (C391, Steven at the Space Center)**: SPECIAL_BATTLE_STEVEN sets BATTLE_TYPE_INGAME_PARTNER (1 << 22) on top of DOUBLE | TWO_OPPONENTS | MULTI. `battleTurns` detects it (`isPartnerBattle`): one player prompt per turn (battler 0; battler 2 runs PlayerPartnerBufferRunCommand, the AI picks), and FIGHT goes through `openFightMenu`, which waits for battler 0's HandleInputChooseAction and repeats UP+LEFT+A until HandleInputChooseMove. Why: the first prompt after a send-out shows "What will X do?" before the menu takes input, the old 30-frame wait lost the FIGHT press, and the log got a second prompt per turn (the following A opened the move menu, B cancelled it). Gated to partner battles only so other battles keep their exact frame timing (RNG). Names: the first battleTurns of the battle logs `[in-game partner: …; player: …]` from gSpeciesNames of gPlayerParty[0..2] / [3..5] (all six slots decoded with `getLayout()` + decodePartyMon; readState stops at gPlayerPartyCount), failing if a species is on both sides. Battle text gives player-side mons no prefix ("METANG used REFLECT!"; side effects read "Ally's REFLECT raised DEFENSE"). Send-out menu = PARTY_LAYOUT_MULTI in battle order 0,3,1,2,4,5 (BufferBattlePartyOrder flank 0), so your bench is menu indexes 2-3 (`PARTNER_MENU_BENCH_END` 4). **The battle is lost when the player's three are down, whatever the partner has left** (worn baseline ended 0,0,0,3,100,100). `chooseHalfParty`: menu type byte 8 (`menuType:4`) = PARTY_MENU_TYPE_CHOOSE_HALF 4; ENTER writes slotId+1 into gSelectedOrderFromParty and the 3rd ENTER moves the cursor to CONFIRM (slotId 6) itself; the special sets VAR_FRONTIER_FACILITY = FACILITY_MULTI_OR_EREADER (1-3 mons, HP > 0). Space Center scenario: ON_TRANSITION clears FLAG_INTERACTED_WITH_STEVEN_SPACE_CENTER when VAR_MOSSDEEP_CITY_STATE is 2, so talk twice (intro, then the YES/NO).
