# README & Community Documentation Patterns in ROM Hacks

**Cycle**: 126 | **Date**: March 2026

---

## Key Findings

### Community Standards for ROM Hack GitHub Pages (2025-2026)

Well-documented ROM hacks (PureRGB, Shin Pokemon Red/Blue) use a layered documentation approach:
- **README.md**: Project summary, credits, general info, download/patch instructions
- **Separate files** (FEATURES.md or wiki) for detailed game data (learnsets, locations)
- **GitHub Issues** with templates for bug reporting
- **Legal disclaimers**: "Unofficial, non-commercial, unaffiliated with Nintendo"

### Navigation & Broken Links

PokeCommunity users specifically praise projects where "all links work and info is kept up to date." Broken navigation is a credibility issue — it signals abandonment or carelessness. For Agent Oak specifically, README nav links that point to non-existent sections should be either written or removed.

### Community Interaction Transparency

ROM hack communities value transparency about development process. Projects that explain how decisions are made (especially AI-assisted ones) build trust. Statistics about community input (accepted/deferred/rejected issues) would be novel and align with open-source culture.

### What Players Want in a ROM Hack README

1. What makes this hack different (unique selling points)
2. How to play it (download + patch instructions)
3. Feature list (concise, scannable)
4. Current development status
5. How to contribute or give feedback
