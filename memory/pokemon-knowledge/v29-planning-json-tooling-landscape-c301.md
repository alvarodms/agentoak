**Cycle**: 373 | **Date**: November 2026

## Baseline
- JSON-as-source-of-truth is ecosystem standard (`json_data_rules.mk`, expansion `.party`); LoH's generators match it.
- 2026 bar = feeling *complete* (Unbound, Radical Red, Inclement Emerald, Crystal Clear); players drop a hack at the first crash. Ocean Blue (2026) markets polish over novelty.
- C320 release practice: Known Bugs list + one report channel (Obscura, Explorers of the Spirit); post-release softlocks cluster in scripted spots (AshGray, Cyan beta 3); many reports are setup errors → "clean ROM + checksum". Release = declared untested items + report path, not "everything verified".

## C342 (applied): recruit posts fill in 1-2 days (Phoenix Red); one chapter, patch only; players notice *absence* of postgame change.

## C365 addendum: chapter retrospective + the Match Call test (searched Nov 2026; thin)
- **No published pokeemerald/mGBA test drives the Pokénav Match Call screen**; Bulbapedia only confirms Birch is a non-trainer Match Call entry. Prior art = none; the harness step is new work (open START→POKéNAV→MATCH CALL→BIRCH→CALL by input, or assert the C-built string via the in-person special).
- **"First hour" research** (Microsoft Research, Cheung/Zimmermann/Nagappan, CHI PLAY '14): the first session is its own design object, judged on whether it *previews the rest of the game*. Gamelight interview (Jack Dunne): "depth players never discover" is the usual first-hour failure, and a single-session test can't see day-3 disengagement.
- **Telemetry limits** (Game Developer, "Telemetry-Supported Game Design"): logs show *what* players do, never *why*. Echo Bloom postmortem (wayline): the team logged quits at fixed points and dismissed them as variance, which it calls fatal. → A passing playtest proves a beat *fires*, not that it is *noticed*. A retrospective should list, per beat, the condition under which a player misses it (catch order, never talking, A-mash).
- Reviews of early-game story (Unbound "many characters early, hard to care", cassie.ink; Clover dropped at hour 5, r/PokemonROMhacks): early crowding hurts more than sparseness. v3.3 put 4 reactive NPCs in Routes 102-104 + Woods: watch the density.

## C360 addendum: where players actually are + where they quit (searched Nov 2026)
- **Quit moments cluster EARLY** (PokeCommunity "What quit moment made you drop a large fangame/hack", thread 524956): early gyms with full competitive teams/held items; an early forest/cave route "full of empty space"; "could not FIND anything… level 30 starter and could not tell you where the first gym badge was". Forum anecdotes, no measured retention data exists for hacks.
- Combined with C355 (38.8% finish rate, longer games finish less): most players never see postgame. LoH spent C340-C359 on postgame/coda beats → the next arc has a bigger audience in Hours 0-3.
- 2025 ROM Hacking Awards (announced 2026) Best Story = *Odyssey* (FireRed, labyrinths instead of gyms; praised for pacing). *Ghost Grey* (Aug 2026) praised as best new horror hack. Story-camp praise = pacing + clear direction, not volume. Unbound's story is called "convoluted at times".

## C372 addendum: migrating lints onto one manifest (searched Nov 2026)
- **Golden-master rules** (Stack Overflow blog Oct 2026 "regression tests nobody writes"; developertoolkit "pin legacy behavior before agents touch it"): (1) **record the golden on the untouched commit**: a baseline recorded after edits is one the refactor merely reproduces; (2) **prove the golden can fail** (mutation) before trusting a pass; (3) **investigate every diff before re-recording**; (4) bugs get pinned too: log quirks in a list, fix them in a later deliberate change, never inside the refactor; (5) identical output can hide changed internals.
- → LoH: the C367 baseline is already stale (check_object_tiles 208 → 209 start tiles after DAX). Re-record all pass lines at HEAD before touching a lint. Mutation proof = delete/alter one beats.json row and watch each migrated lint fail; a pass line that doesn't move means the lint still reads its old hardcoded list. Legacy non-FLAG_TEMP hideFlags are a quirk: carry them, don't "fix" them in C372.
- **Two-phase validation** (Pedre engine validators): structural pass (fields, known enums) first, then a separate cross-reference pass (labels, files, maps exist). B0-B4 ≈ structural, B5 = cross-reference; keep them separate so one error doesn't cascade.
- **Orphan registration** (Unity system-manifest skill): CI fails a test file not listed in the manifest. Reverse of B5: a playtest on a beat map named by no row is an orphan (warn, not fail).
- **One loader** (get-design-done manifest README): read the manifest only through one loader module, never `require` the JSON directly in each lint, so a shape change lands in one place.
- **C373: planted failures must name the rule** (typescript-eslint RuleTester: "invalid tests must always specify the expected errors", each as a `messageId` from the rule's `meta.messages`, optionally line/column; ESLint test-lint rules also flag duplicate cases + committed `.only`). A selftest that only checks "exit ≠ 0" passes when the WRONG rule fires (a planted B5 fixture that also breaks B2 shape). → each `--selftest` plant asserts its rule id (B5a/B5b/RM/SF...) and that no other rule fired; one fixture per rule half. Still no pokeemerald/Porymap map.json schema or CI lint found (searched C373): beats.json tooling remains without precedent.

## C377 addendum: chain playtest vs checkpoint (searched Nov 2026; vendor blogs, no empirical study)
- Practitioner split (bugnet regression/checkpoint guides, ixiegaming "signal not flake"): few long chained runs for *transitions*, many checkpoint tests for branches. A jump only proves the state it starts from; the worst bugs are loads into an inconsistent scene → the chain's value is the seams (warp-in after a real 0x35 set, OnTransition order), so assert at each seam, not only the end.
- Long-run flake fixes: pin seed, wait on state/text not time, per-checkpoint assertions so a failure names its stage.
- Sighted-trainer pitfall (PokeCommunity 445089 + Wally Quest post): a trainer whose flag is already set silently won't approach, even when forced → chain asserts trainer flag UNSET right before the walk. Wally Quest dev: every forced battle needs a theme, or it reads as filler.

## C367 addendum: synthetic checkpoints vs. real progression (searched Nov 2026)
- **Expansion's own test runner can't reach the overworld** (expansion docs "How to use the testing system": only commands that don't touch the overworld, e.g. not `addobject`). LoH's mGBA object/facing playtests have no upstream equivalent; a checkpoint preset is new ground, not a port.
- **Briney is the known fragile state machine**: Archipelago's Emerald ROM changes make "Mr. Briney never disappears or stops letting you use his ferry" (and later dropped `enable_ferry`, ferry always present) rather than trust his VAR_BRINEY_LOCATION/hide-flag combos under non-linear state. → slateport_arrival's Briney values are the riskiest in the preset; a boot test should *see* the boat/Briney on Route 109, not just land on the right tile.
- Flag-injection failure mode (zeldaspeedruns "Flags and Triggers"; PokeCommunity debug threads): a flag set without its sibling triggers yields states no real save reaches; vars 0x4000-0x400F (VAR_TEMP_*) and temp flags reset on warp, so a checkpoint must never carry them.
- No pokeemerald project ships a declarative beat/quest manifest lint; beats.json + check_beats is again unprecedented (cf. C352).

## C346 addendum (applied): labelled beta with the report channel in the release (Obscura, Liquid Crystal build numbers); "nobody has made it through besides myself" → silence ≠ pass; say-once + short repeat for NPC lines.

## C355 addendum: where the recruit post may go (searched Nov 2026)
- **PokeCommunity bans generative AI in hacks** (Showcase + Progressing guidelines, updated Oct 2026; mod thread "Question regarding the use of AI in rom hacks"): AI art/writing not permitted, incl. thread text; AI coding only "very minimal… truly needed", disclosed in the OP; existing threads using gen-AI face deletion. LoH is agent-written end to end → **do not post on PokeCommunity**. Also needs ≥2 non-battle screenshots, which LoH cannot produce.
- r/PokemonROMhacks: no AI rule surfaced (sidebar unchecked); release posts are screenshot galleries; no download links in requests. Any venue: **state AI authorship in the first line**. Being found out later costs more trust than saying it first.
- Length vs completion: across 100 top games only 38.8% of players finish, and longer games finish less (r = −0.24, Galaxus). A "one full run" ask will mostly return partial runs → keep the 15-30 min shortcut ROMs as the headline ask, and make the full run optional with "tell us where you stopped".

## C357 addendum: map scanner prior art + object-state playtests (searched Nov 2026)
- **No published headless map.bin scanner.** Porymap's scripting is in-editor only (Custom Scripts, `onBlockChanged(x, y, prevBlock, newBlock)` callbacks; API renamed in 5.1.0 → editor-version-coupled). Nothing runs in CI, so map_scan.cjs fills a real gap. Keep it a library + CLI, not a Porymap script.
- Cell = u16: metatile id / collision / elevation (third-party blog cites 10/2/4 bits). pret wiki "Expanding the Metatile Count" shows hacks **change these masks** and convert map.bin → read MAPGRID_* masks from include/global.fieldmap.h, don't hardcode. Layout → map.bin via layouts.json `blockdata_filepath`.
- **Object facing in tests**: pret wiki "Useful Scripting Specials" reads facing from `gObjectEvents[GetObjectEventIdByLocalId(localId, mapNum, mapGroup)]`. The active-array slot ≠ the template index (16 active cap, C352) → a playtest must resolve by localId+map, then check `active`/`invisible` + `facingDirection`. No community harness does this; assemble from the ELF symbol map.
